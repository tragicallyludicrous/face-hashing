# Flux.2 Klein + PuLID — identity round-trip MVP (RunPod)

The Flux-based MVP. **Goal of this milestone: prove the identity pipe, not the hash.**
Take a photo, extract its *own* ArcFace identity, and re-render the face from that identity
with Flux.2 Klein + PuLID. With no hash applied, the output should look like the **same
person** in the **same scene** — a null test. Once that's clean, Stage-2 drops in one node
that turns the identity into a deterministic *different* person (see [The hash](#7--where-the-hash-plugs-in-next-step)).

Why Klein: the distilled Flux.2 (9B) fits the **RTX PRO 4500's 32 GB** natively at fp8 with
headroom for PuLID + the text encoder, and samples in **4 steps**. Big quality jump over the
SDXL/InstantID path, no fp8-squeeze gamble like full Flux.2-dev.

- **Workflow:** [`workflows/FLUX2_pulid_roundtrip.json`](workflows/FLUX2_pulid_roundtrip.json)
  (generated by [`build_flux2_pulid.py`](build_flux2_pulid.py) — edit the builder, never the JSON
  by hand). It lives in `comfy/workflows/`, which `pod_bootstrap.sh` symlinks as ComfyUI's canvas
  workflows folder — so on a migrated pod it shows up in the sidebar after `git pull`.
- **Target:** RunPod, **RTX PRO 4500** (32 GB GDDR7, Blackwell / sm_120), ComfyUI at `$COMFY`.

```
LoadImage(photo) ─┬─ image  → ApplyPuLIDFlux2 ──────────────┐  (identity: antelopev2 ArcFace)
                  └─ pixels → VAEEncode → SetLatentNoiseMask │
                                              (face_mask) ───┴→ KSampler → VAEDecode → SaveImage
UNETLoader(Klein) → ApplyPuLIDFlux2 → KSampler        (masked denoise keeps the scene/pose)
```

---

## 0 — Prereqs

A running ComfyUI on the pod. `export COMFY=/workspace/ComfyUI` (adjust to your pod).

> **ComfyUI must be recent.** Flux.2 uses a sampling architecture introduced **after ComfyUI
> 0.9.2** — update to the latest/nightly (`cd $COMFY && git pull && pip install -r requirements.txt`).
> An older build won't recognize the `flux2` CLIP-loader type and fails to load this graph.

> **Blackwell caveat (read first).** The RTX PRO 4500 is sm_120. fp8 Flux + onnxruntime-gpu
> need CUDA 12.8+ and a torch built with sm_120 kernels (torch ≥ 2.7 cu128). An older torch
> runs but emits **black / pure-noise images** with no error (same failure class as the SDXL
> MPS confetti). Verify before downloading 30 GB of weights:
> ```bash
> python -c "import torch; print(torch.__version__, torch.version.cuda); \
>            print('sm_120', 'sm_120' in torch.cuda.get_arch_list())"
> ```
> Expect cuda `12.8`+ and `sm_120 True`. If not, install a matching wheel
> (`pip install --pre torch --index-url https://download.pytorch.org/whl/cu128`).

## 1 — Install the PuLID-Flux2 node

> **Fast path — let the bootstrap do §1 + §2.** On a fresh/migrated pod, run
> `HF_TOKEN=hf_xxx bash /workspace/face-hashing/comfy/pod_bootstrap.sh`. It's idempotent and does
> all of this: finds ComfyUI's venv python the safe way, installs the deps **with `ml_dtypes>=0.5.1`**
> (and verifies `float4_e2m1fn`), clones the InstantID + PuLID-Flux2 + FaceHash nodes, writes
> weights into ComfyUI's `models/` (already on the volume), and fetches the gated Klein weights if `HF_TOKEN` is set. Then restart
> ComfyUI. The manual steps below are what it automates — read them once to understand the moving
> parts, or if you're not on the pod template.

```bash
cd $COMFY/custom_nodes
git clone https://github.com/iFayens/ComfyUI-PuLID-Flux2.git

# Install into the SAME python ComfyUI runs with — bare `pip` on RunPod often misses ComfyUI's venv,
# and the deps then look "installed" but aren't importable by the node (→ it vanishes / errors at run).
# Derive it from the process's VIRTUAL_ENV (or argv0). Do NOT use `readlink -f /proc/$PID/exe` — that
# resolves a venv's symlinked python to the BASE interpreter, so pip installs into the wrong env.
PID=$(pgrep -f '[m]ain.py'|head -1)
VENV=$(tr '\0' '\n' </proc/$PID/environ | sed -n 's/^VIRTUAL_ENV=//p')
PYBIN=${VENV:+$VENV/bin/python}; PYBIN=${PYBIN:-$(tr '\0' '\n' </proc/$PID/cmdline | head -1)}
echo "ComfyUI python = $PYBIN"
"$PYBIN" -m pip install insightface onnxruntime-gpu open-clip-torch safetensors
# ⚠️ Do NOT use the node README's `ml_dtypes==0.3.2`. It's too old for a Flux.2 / Blackwell ComfyUI
# (no `ml_dtypes.float4_e2m1fn`, the FP4 dtype modern torch needs) and silently breaks the import —
# the node loads but registers zero nodes. Keep ml_dtypes current instead:
"$PYBIN" -m pip install -U "ml_dtypes>=0.5.1"
# Do NOT pip install eva_clip from GitHub — the node bundles its own EVA-CLIP path.
```

It registers: `PuLIDInsightFaceLoader`, `PuLIDEVACLIPLoader`, `PuLIDModelLoader`,
`ApplyPuLIDFlux2`, `PuLIDFacePreview`.

> $HF_TOKEN` and e.g. `hf download Comfy-Org/flux2-klein-9B

## 3 — Load the workflow + your inputs

1. Open `FLUX2_pulid_roundtrip.json` from the canvas sidebar (the bootstrap symlinks
   `comfy/workflows/` there, so `git pull` on the pod populates it). **Restart ComfyUI** first so
   the new node is registered.
2. **`LoadImage`** → your photo (default points at `zack-normal-06.jpeg`).
3. **`LoadImageMask`** → a white-on-black mask of the **face region** (default
   `zack-normal-06_mask.png`, channel `red`). This is what gets regenerated; everything outside
   it is pixel-preserved. Reuse the mask you built for the M2 inpaint, or generate one with a
   face-parse node.
4. **`PuLIDInsightFaceLoader`** provider = **`CUDA`** (already set; fall back to `CPU` if
   onnxruntime-gpu has no sm_120 kernels — face detection is cheap, the diffusion stays on GPU).

> **Size the photo first.** Flux.2 needs **both dimensions divisible by 16**. This graph encodes
> the raw photo with no resize node, so pre-process to a clean size — ~1024 px long edge, each
> side a multiple of 16 (1024×1024, 1024×768, …). The **mask must match the photo's dimensions**.
> (Don't use `ImageScaleToTotalPixels` for this — it's unreliable for I2I.)

> Same image feeds `ApplyPuLIDFlux2.image` (identity) and `VAEEncode.pixels` (the scene). That
> *is* the round-trip: the face's own identity, re-rendered into its own photo.

## 4 — Settings (and what to tune)

| Node | Setting | Default | Notes |
|---|---|---|---|
| `ApplyPuLIDFlux2` | `strength` | **1.3** | bump to **1.4** if identity is weak; lower if skin looks plasticky |
| `KSampler` | `steps` | **8** | for the **distilled** file (4-step native); inpaint at denoise<1 wants a few more. **Base file → ~20.** |
| `KSampler` | `cfg` | **1.0** | correct for **distilled** (negative is ignored at cfg 1). **Base file → 3.5–5** and fill in a negative prompt. |
| `KSampler` | `denoise` | **0.85** | ↑ toward 1.0 = more freedom to change the face, ↓ = stays closer to original pixels |
| `KSampler` | sampler/scheduler | `euler` / `simple` | the Klein-recommended pair (avoid Euler **Ancestral**) |

> The defaults assume the **distilled** `flux-2-klein-9b-fp8`. If you downloaded `…-base-9b…`,
> set steps ~20 / cfg ~3.5–5 — otherwise it renders flat and grey.

**Sanity pass first.** Before trusting the inpaint, confirm identity in isolation: temporarily
swap `SetLatentNoiseMask` for an `EmptyFlux2LatentImage` (1024×1024) and set `denoise 1.0`,
`steps 4` — pure PuLID portrait. If *that* doesn't look like the person, fix identity
(strength, the antelopev2 path, the mask cropping the face in `ApplyPuLIDFlux2.image`) before
touching the inpaint tail.

## 5 — Run + expected result

Queue the prompt. First run downloads EVA-CLIP (~800 MB) and builds the antelopev2 session.

- **Pass:** the masked face is re-rendered as the **same person**, same pose, same lighting,
  blended into the original scene. That's the identity pipe proven.
- The `facehash_flux2_pulid_*.png` lands in `$COMFY/output/`.

the `-fp8` / `fp8mixed` filenames.

## 6 — Inpaint vs. edit (if Klein fights the mask)

This graph does **masked inpaint** (keep scene, regen face). The distilled Klein is calibrated for
a **4-step, full-denoise** schedule, so partial-denoise inpaint pushes it off-distribution and can
go mushy. The graph ships denoise 0.85 (keeps the original face's structure — good for *seeing*
the null test work); if that's soft, here are the outs, in order of how well they fit the distillation:

- **Match the distilled regime (most robust on distilled):** `denoise` **1.0**, `steps` **4**. Fully
  regenerates the masked face from the identity (exactly what the eventual hash wants anyway) and
  stays in the model's trained 4-step schedule. You lose original-face structure inside the mask,
  but everything outside it is still pixel-preserved.
- **Stay partial:** keep denoise<1 but raise `steps` → 10–12 and `denoise` → 0.9 (more original
  structure retained, at some softness risk).
- **Switch to edit:** the PuLID repo's own
  [`workflows/PuLID_Flux2_(Klein).json`](https://github.com/iFayens/ComfyUI-PuLID-Flux2/tree/main/workflows)
  uses Flux.2's native edit path (`ReferenceLatent` + full denoise) instead of a mask — better
  for distilled Klein, but it re-renders the whole frame rather than compositing into the
  original pixels. Use it to confirm identity quality, then come back to the mask for the
  paste-back.

## 7 — Where the hash plugs in (next step)

This MVP runs **stock** PuLID — identity in, same identity out. Stage-2 makes it a *different*
deterministic person by hashing the embedding, exactly as `FaceHashApplyInstantID` did for SDXL.

In `ComfyUI-PuLID-Flux2/pulid_flux2.py`, `ApplyPuLIDFlux2.apply()` (~L215):

```python
faces = face_analysis.get(img_np)
face  = faces[face_index]
id_embed = torch.from_numpy(face.embedding).unsqueeze(0)   # ← 512-d antelopev2 ArcFace
id_embed = F.normalize(id_embed, dim=-1)
```

Plan for `FaceHashApplyPuLIDFlux2` (build once we can introspect the installed node on the pod):
subclass `ApplyPuLIDFlux2`, and in `apply()` wrap `face_analysis.get` so each returned
`face.embedding` is replaced by `arcface_keymix_v1(face.embedding, key, offset)` *before* PuLID
reads it. Norm-preserving, so `F.normalize` downstream is unaffected.

- This is **antelopev2** — the same backbone as `ComfyUI_FaceHashDepth`'s `antelope` column, so
  one `key` (+ `transform`/`gallery`/`basis`) stays consistent across **geometry and texture**.
  Use `arcface_keymix_whitened_v3` for an on-manifold synthetic identity (no real face targeted),
  matching the InstantID/Depth nodes.
- ⚠️ **EVA-CLIP leak.** PuLID also feeds an EVA-CLIP crop of the face into `IDFormer`
  (`pulid_flux2.py:~255`, concatenated with `id_embed`). Hashing only the ArcFace branch leaves
  EVA-CLIP describing the *original* face → a partial scramble, not the clean isometric swap
  InstantID gave (InstantID's identity is ArcFace-only). To fully sever the original identity
  we'd also need to drive EVA-CLIP from the hashed/synthetic face (e.g. render the hashed
  identity to a crop first, or zero the CLIP branch). Evaluate visually before deciding.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Model loads as corrupt / `HeaderTooLarge` / tiny `.safetensors` | gated download saved an HTML/empty page — accept the license + re-auth, re-pull (§2) |
| Graph won't load / `flux2` CLIP type unknown | ComfyUI older than the Flux.2 update — `git pull` to nightly (§0) |
| `ml_dtypes has no attribute 'float4_e2m1fn'` / PuLID node imports but isn't in the menu | ml_dtypes downgraded by the `0.3.2` pin — `"$PYBIN" -m pip install -U "ml_dtypes>=0.5.1"`, restart (§1) |
| Black / noise output, no error | torch not built for sm_120 (Blackwell) — see §0 |
| Errors at `VAEEncode` / latent-size mismatch | photo dims not divisible by 16, or mask ≠ photo size (§3) |
| Distorted / shifted colors | wrong VAE — must be `flux2-vae`, not a FLUX.1 / SDXL VAE |
| Washed-out, flat, grey | settings/variant mismatch — base file run at cfg 1, or distilled run at cfg 4 (§2/§4) |
| `No face detected` / empty embedding | provider not `CUDA` (try `CPU`), or antelopev2 files missing/misplaced |
| OOM at load | a non-fp8 weight slipped in — check `-fp8` / `fp8mixed` filenames |
| Identity too weak | `strength` → 1.4; confirm the mask isn't cropping the face out of `ApplyPuLIDFlux2.image` |
| Mushy / smeared face | distilled-Klein + partial denoise — try denoise 1.0 / 4 steps, or the edit graph (§6) |
| Node missing after install | restart ComfyUI; check the `pip install` (§1) ran in the ComfyUI venv |
